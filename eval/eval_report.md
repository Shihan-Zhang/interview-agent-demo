## 方法论说明

- **区分结果评估(Outcome Eval)和轨迹评估(Trajectory Eval)**:Task Success Rate 要求工具选对 *and* 最终结果对,Tool Call Accuracy 单独衡量过程是否正确——两者分开报告是因为'结果蒙对了但过程错了'和'过程对但结果展示错了'是两种不同的失败,需要不同的修复方式。
- **为什么要 Bootstrap 置信区间而不是只报点估计**:12个任务的点估计方差很大,不加区间会让人误以为这个数字很精确。
- **专门测了工具报错场景(t11/t12)**:检验 Agent 在工具失败时会不会'编造一个假成功'——这是真实 Agent 系统里最隐蔽的失败模式之一,比'不会用工具'更危险,因为它看起来像是成功了。
